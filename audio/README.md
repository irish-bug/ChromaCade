# audio/

Not the audio engine — that's `audio_engine.py`, at the repo root alongside `chromacade.py` and its other supporting modules (see top-level `CLAUDE.md`'s Repo state section). This directory holds audio-related assets and standalone scripts instead:

- `boot_chime.sh` / `chromacade-boot-chime.service` — the boot chime, a separate systemd unit from `chromacade.service` (repo root). Plays `prompts/plinkplonk_theme.wav` (ChromaCade's own theme, as of 2026-08-31) — replaced the earlier 3-way spoken-greeting cycle (`hello`/`whats_up`/`lets_go.wav`, added 2026-08-27); those files are still present but no longer referenced.
- `nopes/` / `yays/` / `prompts/` — recorded Tutor/Simon feedback clips (personal recordings, git-tracked). `sound_pools.py` (repo root) picks which file plays when; see its docstring for the six pools and their rules.
- `play_melody.py` — a standalone script, predates `chromacade.py`.
- `bari-uke-mic.sf2` — custom soundfont: a single mic'd baritone ukulele instrument (recorded in Audacity, built/tuned in Polyphone; see `docs/open-questions.md`'s "Custom fonts recorded from real tenor/baritone ukulele" entry). Tracked as a named exception to the `audio/*.sf2` gitignore rule below it — everything else under that pattern (piezo version, work-in-progress builds) stays untracked until finished. **Not yet wired into `audio_engine.py`'s `FONTS` list** — still just an asset, played ad hoc via `fluidsynth -g 4.5 -a alsa audio/bari-uke-mic.sf2` for listening tests. Known open issue: quieter than the stock GM instruments (see project memory / open-questions for the fix — likely re-normalizing the source `.wav`s, not more Polyphone attenuation). Will eventually be folded into a combined trimmed soundfont alongside the piezo version and the curated GM subset.
